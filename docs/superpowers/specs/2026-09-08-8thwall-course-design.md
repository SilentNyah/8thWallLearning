## 1. 解決する問題と、いま取り組む理由

8th Wall は 2026-02-28 にホスティング事業を終了し、無償・オープンソースへ移行した。この結果、**ウェブ上に存在する 8th Wall のチュートリアルは、そのほぼ全てが再現不能になった**。既存教材は「クラウドエディタでプロジェクトを新規作成する」ことを出発点にしているが、そのクラウドエディタはもう存在しない。

一方でエンジン本体は健在で、アカウント登録も App Key も不要になり、参入障壁はむしろ下がっている。**「動く技術」と「使える教材」の間に空白が生まれている**状態であり、日本語圏ではその空白がさらに大きい。

いま取り組む理由は、この空白が一時的なものだからである。OSS 移行直後の現在は、ローカル前提の手順を書いた教材が事実上存在しない。

## 2. 成功基準

1. **R1 公開時点で、8th Wall 未経験の Web 開発者が README だけを見て Android 実機に AR を表示できる。** 第三者 1 名に実際に試してもらい、詰まった箇所を記録して計測する
2. 公開中の全レッスンで CI が green である
3. 公開中の全レッスンに、実機検証を通した日付のフッターが存在する
4. **`8thwall.com` および `8th.io` への依存がゼロである**（これらは消滅が見込まれるドメイン）

## 4. 前提となる事実（2026-09-08 時点で確認済み）

- 8th Wall のホスティング、開発者ログイン、クラウドエディタ、XR Studio は **2026-02-28 に停止**した
- 既存の公開済み体験は 2027-02-28 まで稼働し、その後データは削除される
- 8th Wall は https://8thwall.org/ で無償・オープンソースとして提供されている。**アカウント不要、App Key 不要**
- 大半のコンポーネントは MIT ライセンス。**XR Engine のみ、無償だが商用利用に制限のあるバイナリ**として配布される
- 本リポジトリは OSS 版の A-Frame「World Effects」サンプルであり、エンジンを jsdelivr の `@8thwall/engine-binary` から読み込んでいる。App Key の記述は存在しない
- 動作する機能: World Effects、Absolute Scale、Image Targets、Face Effects、Sky Effects
- 画像ターゲットの生成は、旧クラウドコンソール機能から **Image Target Processor CLI** に置き換わっている

## 5. 制約

- **実機は Android Chrome と PC のみ。** iOS は検証できないため、保証しない旨を明記する
- **Git LFS**: 現行 `.gitattributes` は `src/assets/**` と `external/**` を LFS 追跡している。GitHub 無料枠は 1GB/月であり、レッスンごとに 3D モデルを増やすと逼迫する
- **公式ドキュメントの消滅リスク**: `www.8thwall.com/docs` への深いリンクは張らない。必要な情報はリポジトリ内に自前で記述する
- **単一エントリのビルド構成**: `config/webpack.config.js` はエントリもテンプレートも 1 本のみ。複数レッスンに対応するには再設計が必要
- **`.github/` が存在しない**: README は GitHub Actions による自動デプロイを謳っているが、**この写しには設定ファイルが無い**。ワークフローは自前で作成する
- **執筆者は 1 名**。完成しないことが最大のリスクであり、あらゆる判断で「完成可能性」を優先する

## 7. リポジトリ構造とビルド設計

### 採用方針: 段階移行ハイブリッド

第 1 章はビルドレス（素の HTML + CDN）、L05 を移行レッスンとして webpack を導入し、以降はマルチエントリ webpack 構成とする。

この方針を採る理由は、対象読者にとって最大の脱落ポイントが 3D の概念ではなく**最初の環境構築**だからである。第 1 レッスンが「HTML を 1 枚開くだけ」で始まることで AR が動く体験を最短で提供でき、webpack は前提知識ではなく**必要になった時点で教える学習対象**に変わる。

### ディレクトリ構成

```
/
├─ README.md                  コースのトップ（目次・前提・進め方）
├─ lessons/
│  ├─ manifest.json           レッスン定義の唯一の真実
│  ├─ 01-first-ar/            ビルドレス
│  │  ├─ README.md
│  │  └─ index.html
│  ├─ 05-why-build/           移行レッスン（前後の構成を並置）
│  ├─ 06-tap-to-place/        webpack 構成
│  │  ├─ README.md
│  │  ├─ index.html
│  │  └─ app.js
│  └─ ...
├─ shared/assets/             全レッスン共有アセット（LFS 対象）
├─ config/webpack.config.js   マルチエントリ化
├─ external/                  8frame 等（現状維持）
├─ scripts/                   lint スクリプト
├─ .github/workflows/         CI（新規作成）
└─ docs/superpowers/specs/    設計ドキュメント
```

### `manifest.json` を単一の真実とする

各レッスンの `id` / `title` / `dir` / `mode`（`static` または `bundled`）を 1 ファイルに集約し、そこから **webpack のエントリ**と**索引ページ**を生成する。レッスン追加時に編集する箇所が 1 箇所に固定され、章立てと実体が乖離しない。

### ビルドレスレッスンの二重の成立条件

第 1 章のレッスンは、**読者側では npm を一切使わずに動作する**必要がある（それがこの章の存在理由であるため）。同時に、著者側では全レッスンをまとめて確認したい。

これを両立させるため、ビルドレスレッスンは**相対パスと CDN のみ**で完結させ、webpack 側は `CopyWebpackPlugin` で `dist` に写すだけとする。

- 読者: `npx serve lessons/01-first-ar` のみで動作する
- 著者: `npm run serve` で索引ページから全レッスンを通しで確認できる

### 既存コードの行き先

現在の `src/` のコードは、**L06 の土台として `lessons/06-tap-to-place/` へ移動する**。

アセットについては**単一の規則を適用する: ライセンスを出典付きで明示できるアセットのみを公開コースに残し、明示できないものは除外する。** 第 10 節のとおり `cactus.glb` は出典が消滅しており検証不能であるため除外する。`sand.jpg` と `preview.gif` にも同じ規則を機械的に適用する（実装時に出典を確認し、確認できなければ除外する。判断を保留しない）。

除外したアセットは削除ではなく、第 12 節の復元点コミットに含めた状態で履歴に残す。

### 順序上の注意（重要）

本リポジトリには**コミットが 1 つも存在しない**。LFS ポインタも履歴に入っていないため、`.gitattributes` の追跡パスを変更するなら**現在が唯一の無痛タイミング**である。

したがって実装は次の順序を厳守する。

1. 素のサンプルの状態で 1 コミットし、復元点を作る
2. その直後に `.gitattributes` を `shared/assets/**` および `lessons/*/assets/**` へ書き換える
3. 以降、ディレクトリ再編に着手する

### 実機確認の手段

カメラ AR には HTTPS が必要である。既存設定は `config/webpack.config.js` の `allowedHosts` で ngrok を前提としているが、読者にトンネル用アカウントを要求するのは障壁となる。

**第一候補は Chrome DevTools のポートフォワーディング**である。Android 側では転送先が `localhost` 扱いとなり、`localhost` は secure context であるため、証明書もトンネルも無しでカメラが動作すると見込まれる。

**ただしこれは未検証の仮説である。** L01 の執筆前に実機で検証し、成立しない場合は ngrok 手順にフォールバックする。**読者向け README には、検証を通過した方法を 1 つだけ記載する**（初学者に選択肢を提示すると詰まるため、併記はしない）。

## 8. レッスンの内部構造とドキュメント様式

公開教材の品質は、個々の説明の巧拙より**様式の一貫性**で決まる。拾い読みする読者に毎回書式を学び直させないため、テンプレートを固定する。

### レッスン README の固定構成

```markdown
# L06 タップして置く

## このレッスンでできるようになること
（動詞で 1〜3 個。「〜を理解する」は禁止、「〜を書ける」とする）

## 前提
（前レッスン、必要なもの）

## まず動かす
（最短手順。解説より前に置く）

## 解説
（本文）

## つまずきポイント
（症状 → 原因 → 対処 の 3 点セット固定）

## やってみよう
（任意。解答は用意しない）

---
検証：YYYY-MM-DD / Android Chrome <version> / engine <version>
```

**「まず動かす」を解説より前に置くことが、この様式で最も重要な判断である。** 読者は 3D 初心者であり、動く実物を見る前に座標系の説明を読まされると離脱する。

### コードの置き方

各レッスンフォルダに**完成コードを置く**。写経形式は採らない。拾い読み前提のコースにおいて、L09 から読み始めた読者が L01 からの積み上げを要求されると詰むためである。

前レッスンからの変更は README で明示する。差分の示し方は行数で機械的に決める。**30 行以下のファイルは全文掲載、それを超える場合は変更箇所のみ**。都度判断で悩まないためのルールである。

コード内コメントは**日本語**とし、識別子は英語とする。

### つまずきポイントの書式

このセクションが既存の英語チュートリアルに対する最大の差分であるため、書式を固定する。

> **症状:** カメラは起動するが、モデルが真っ黒に見える
> **原因:** ライトを置いていない。A-Frame のデフォルトライトは、シーンに `light` を 1 つでも書くと無効化される
> **対処:** `<a-light type="ambient">` を追加する

症状から引ける形にすることで、検索流入した読者がそのまま解決できる。

### バージョンの厳密固定（サンプルからの意図的な逸脱）

現行サンプルの `src/index.html` は `@8thwall/xrextras@1` のように**メジャー範囲指定**を用いている。通常のプロジェクトでは妥当だが、**教材では採用しない**。上流が更新された瞬間に、記述した説明と読者が見る挙動が乖離するためである。

全レッスンで**厳密なバージョン指定**に置き換え、代わりに各レッスン末尾のフッターで検証日と版を明示する。古びること自体は避けられないが、**古びたことが読者に見える**状態にはできる。

## 9. 検証と CI

### 「動作確認済み」の 3 段階

| 段階 | 内容 | 実施者 |
|---|---|---|
| 1. 構造検証 | 全レッスンがビルドでき、様式が揃っている | 機械（CI） |
| 2. PC 検証 | PC Chrome で開き、コンソールエラーが出ない | 人（手動） |
| 3. 実機検証 | Android Chrome でカメラ AR が実際に動作する | 人（手動） |

**レッスンフッターの検証日は、段階 3 を通過したときにのみ更新する。** これが本コースにおける「検証済み」の定義である。

### 機械化する検証

フレームワークは構築せず、**100 行程度の Node スクリプト 1 本**とする。

- `manifest.json` と実フォルダの整合（片方にしか存在しないレッスンを検出）
- 各 README の必須見出しが揃っているか
- 検証フッターの存在と日付形式
- **CDN URL の浮動バージョン検出** — `@8thwall/xrextras@1` のような範囲指定をエラーとする
- リポジトリ内部リンクの切れ検出
- `npm run build` が全 bundled レッスンで成功すること

このうち**最も価値が高いのは浮動バージョンの検出**である。14 本を数か月かけて執筆すれば、貼り付けミスは必ず混入する。

### CI

`.github/workflows/` を新規作成する（既存の設定は存在しない）。

- `push` / `pull_request`: build + lint
- `main` への push: GitHub Pages へデプロイ

分割リリースを採る以上、章を追加するたびに手動デプロイするのは事故のもとであるため自動化する。

### 機械化しないと決めたこと

**AR が「正しく見えるか」は自動化しない。** 平面検出の安定性やモデルの接地といった判断は実機で人間が見るしかなく、ここへの投資はコースを前進させない。

**Playwright による PC ブラウザの自動巡回は v1 では作らない。** カメラ AR は PC では本質的に検証できず、得られるのは構造検証の重複に過ぎない。章が 10 本を超えて手動巡回が苦痛になった時点で再検討する。

### 実機検証の運用

レッスン単位ではなく**章単位**で回す。章を書き終えた時点でその章の全レッスンを Android で通しで実行し、通過したものだけフッターを更新して公開する。1 本ごとに端末を出す運用は継続しない。

## 10. 公開・ライセンス

### 同梱 3D モデルのライセンス問題

現行 README は `cactus.glb` を「Toon Cactus by PolyChromic」として Sketchfab にリンクしているが、**2026-09-08 時点で当該モデルは Sketchfab 上から削除されている**。ライセンス種別も作者情報も検証できない。

README がモデルを**別途 attribution している**事実自体が、MIT のコード本体とは別ライセンスであることを示唆しており、再配布可否が不明なまま公開リポジトリに置くことは避ける。

**対処:**

- `cactus.glb` は公開コースから除外する
- 第 1〜3 章の大半は **A-Frame のプリミティブ**（`a-box` / `a-sphere`）で記述する。教材としてもその方が優れており、ファイル読み込みという不確定要素が消える
- GLB が真に必要なレッスンでのみ、**ライセンスが明示された CC0 アセット**（Kenney.nl 等）を使用し、出典を記載する

この対処は LFS 容量の制約も同時に緩和する。

### ライセンス 3 層

| 対象 | ライセンス |
|---|---|
| コース本文（文章） | **CC BY 4.0** |
| サンプルコード | **MIT**（既存 `LICENSE` の 8th Wall, Inc. および Niantic Spatial, Inc. の表記を保持） |
| 8th Wall XR Engine バイナリ | **無償だが商用利用に制限あり** — L00 で明示する |
| 3D アセット | 各アセットの出典とライセンスを個別に記載 |

エンジンの商用制限は、読者が業務利用を試みた際に問題となるため、L00 で曖昧にせず記述する。

### 外部依存の除去

現行 README は QR コードを `https://8th.io/qr` で生成している。**`8th.io` は 8th Wall のドメイン短縮サービスであり、ホスティング停止に伴い消滅する可能性が高い。**

QR は**ビルド時にリポジトリ内で生成**し、外部サービスに依存しない形とする。実機で開く導線は本コースの生命線であり、他者のドメインに預けない。

## 12. 実装の大まかな順序

詳細な実装計画は本ドキュメント承認後に別途作成する。ここでは順序の骨子のみ記す。

1. **復元点の作成** — 素のサンプル状態で 1 コミット
2. **`.gitattributes` の修正** — LFS 追跡パスを新構成へ変更（コミット前でなければ無痛に行えない）
3. **`dev/null/` の削除** — Git LFS フックの複製であり不要（削除は破壊操作のため実施前に確認する）
4. **ディレクトリ再編** — `lessons/` `shared/` `scripts/` の作成、`src/` の移動、`manifest.json` の作成
5. **webpack のマルチエントリ化** — `manifest.json` 駆動のエントリ生成と索引ページ生成
6. **lint スクリプトと CI の作成** — `.github/workflows/` の新規作成
7. **実機検証の手段を確定** — ポートフォワーディング仮説の検証、駄目なら ngrok へフォールバック
8. **L00–L04 の執筆と章単位の実機検証**
9. **R1 公開**
10. 以降 R2〜R5 を同じ流れで反復

### 押し返した箇所

「後半でビジュアルエディタも扱う」という当初の希望に対し、**エディタは並行トラックではなく最終章の薄い付録 1 本に限定する**よう押し返し、合意を得た。理由は、GUI 手順がスクリーンショット依存で腐りやすいこと、検証環境が 2 つに増えること、OSS 版デスクトップエディタが移行直後で未検証であることの 3 点である。この判断により、**付録が無くてもコース本体が公開可能な状態**が保たれる。
